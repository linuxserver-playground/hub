// reference

Endpoints

Versions, tags, architectures, changelogs and container parameters for every LinuxServer.io image, every build with its packages, layers and changes, the mods index, the PRoot Apps index, and compose, Kubernetes, quadlet and reverse proxy snippets.

Every endpoint is a plain GET with no authentication. Fields that have no value are omitted rather than null. Query parameters are not supported: include_config and include_deprecated are separate files under Compatibility.

// Builds

Every build of an image: the build record, packages, layers and the diff.

GET /api/v1/catalog/{name}/builds.json

List the builds of an image

Every build held by the hub (the newest five per branch), newest first, with links to its files on the image repository's Pages, and the release history per branch. vulnerabilities are the counts of the scan the build made of itself when it was released, never rescanned; the findings are links.vulns, the build's vulns.json on its repository's Pages (the hub serves no copy).

Parameters

  • name path · string required

    The image name, as in ghcr.io/linuxserver-playground/<name>.

Response application/json

BuildsResponse
  • status "OK" required
  • last_updated string required

    When the data was last refreshed, UTC, as YYYY-MM-DD HH:MM:SS+00:00.

  • data BuildsData required
    • image string required
    • builds BuildSummary[] required

      Builds held in data/, newest first.

      • tag string required
      • branch string required
      • release_tag string
      • upstream_version string required
      • semver string
      • ls_build integer required
      • created string required
      • reason string required
      • commit string required
      • test_success boolean
      • base BuildBase required
        • family string required
        • image string required

          FROM reference as written.

        • digest string

          Resolved base digest at build time (amd64).

        • build_version string

          The base image's build_version label.

      • platforms PlatformBuild[] required
        • arch "amd64" | "arm64" required
        • result "success" | "failure" | "cancelled" | "skipped" required
        • digest string
        • size integer

          Sum of compressed layer sizes in bytes.

        • uncompressed_size integer
        • layers integer
        • runner string
        • build_seconds number
      • index_digest string

        The digest of the build's multi-arch index: what an image built on this one records as base.digest, so a base image's build can be found from the images that use it.

      • tags string[]

        Every tag the build published, unprefixed then arch-prefixed: published.tags of its build.json (version.tags for releases made before that field). Floating tags (latest, develop) have moved on to the newest build of the branch since.

      • classification string

        From the diff against the previous build of the branch.

      • vulnerabilities VulnerabilitySummary

        Counts of the scan the build made of itself when it was built, for builds that have one (see links.vulns and its caveats). Not updated after the release.

        • critical integer required
        • high integer required
        • medium integer required
        • low integer required
        • negligible integer required
        • unknown integer required
        • fixed integer required

          The distribution or upstream ships a fixed version.

        • unfixed integer required

          No fix is known: not-fixed and unknown fix states.

        • wont_fix integer required

          The distribution has decided not to fix it for this release.

      • links BuildLinks required
        • build string required
        • diff string required
        • layers map<string, string> required

          Per architecture.

        • packages map<string, string> required

          The hub's package table per architecture; only the newest build of each branch has one. For the others, sbom is the build's syft document.

        • release string
        • pages string required

          The build's folder on its image repository's GitHub Pages (https://<owner>.github.io/<repo>/builds/<tag>/), with a trailing slash: files.<arch>.json.gz, packages.<arch>.json.gz, vulns.json and each architecture's unpacked test report under <arch>/ (see tests.json). Served with access-control-allow-origin: * for the newest 5 builds of each live branch, the builds the hub holds.

        • files map<string, string> required

          files.<arch>.json.gz per architecture on the repository's Pages (under pages): gzip served as application/gzip, without Content-Encoding.

        • sbom map<string, string>

          packages.<arch>.json.gz, the build's syft document, per architecture on the repository's Pages (under pages), served like files.

        • run_json string required

          run.json on the Release: the control plane's record of the workflow run. A download link (Release assets send no CORS headers); 404 for releases made before control attached it.

        • logs_zip string required

          logs.zip on the Release: the run's masked log archive. A download link; 404 for releases made before control attached it.

        • test_report string

          The build's CI results page on the website, <site>/images/<image>/builds/<tag>/ (the hub's own /builds/<image>/<tag>/ only redirects there).

        • tests string

          tests.json: the harness reports per architecture, when any exist.

        • report string

          report.json: the build page aggregate.

        • vulns string

          vulns.json on the repository's Pages (under pages), for builds that scanned themselves: the scan made when the image was built, never rescanned. {image, tag, summary, by_arch, matches, db_date, grype_version, scanned_at, caveats} (CONVENTIONS §6, "Repo Pages"); summary is vulnerabilities, and caveats say how to read the counts. The hub serves no copy.

    • history map<string, HistoryEntry[]> required

      Every release seen per branch, newest first.

GET /api/v1/catalog/{name}/builds/{tag}/diff.json

Get what changed in a build

Packages, config, base, size and Dockerfile changes against the previous build of the same branch.

Parameters

  • name path · string required

    The image name, as in ghcr.io/linuxserver-playground/<name>.

  • tag path · string required

    A release tag, <upstream>-ls<N>.

Response application/json

DiffResponse
  • status "OK" required
  • last_updated string required

    When the data was last refreshed, UTC, as YYYY-MM-DD HH:MM:SS+00:00.

  • data DiffData required
    • diff Diff required

      What changed between a build and the previous build of the same branch.

      • image string required
      • branch string required
      • tag string required
      • previous_tag string

        None for the first build of a branch the hub has seen.

      • classification "upstream" | "packages" | "linuxserver" | "base" | "mixed" | "none" | "initial" required

        upstream: the upstream version changed. packages: only packages changed. linuxserver: the Dockerfile (or a push with no other change) changed with the same upstream. base: the base image digest changed. mixed: more than one of those. none: an identical rebuild. initial: no previous build.

      • reasons string[] required

        The signals behind classification, for humans.

      • upstream ValueChange required
        • from string
        • to string
        • changed boolean required
      • commit CommitChange

        The repository commits compared, with the compare page.

        • from string
        • to string
        • changed boolean required
        • compare_url string

          GitHub's compare page between the two, when they differ.

        • commits CommitEntry[]

          Oldest first, as GitHub lists them (at most 250).

          • sha string required
          • subject string required
